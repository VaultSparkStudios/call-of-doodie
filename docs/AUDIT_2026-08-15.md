## Gameplay Diagnosis

The shipped game is not short on content. It has eight modes, eleven weapons, enemy and boss families, four wave themes, four seeded arena layouts, five dynamic objective families, wave contracts, route choices, hazards, mutations, mastery, ghosts, challenges, replay proof, and a strong defeat-to-revenge loop. The repetition comes from **structural convergence**: nearly every choice returns to one flat-arena, spawn/clear/reward/boss cadence inside the same client-side game loop.

The live architecture court is already red: `App.jsx` is **4,958/5,000 lines**, and its game-loop span is **1,776/1,775**. The first implementation step is therefore a behavior-preserving ModeRules/encounter-lifecycle extraction; Operation Mode comes immediately after it and must not be added inline.

## Recommended Direction

First extract **ModeRules and encounter lifecycle** from the over-budget game loop without changing current behavior. Then build **Operation Mode** as a 12–18 minute, three-act mission graph using BREACH, HOLD, ESCORT, HUNT, SABOTAGE, ESCAPE, and BOSS encounters; give route choices persistent map consequences and let objectives change the arena through doors, pumps, valves, barricades, turrets, hazards, and one bounded watchtower. Keep Endless Waves, Boss Rush, Sewer Zombies, Daily Challenge, and Weekly Gauntlet as Arcade/mastery playlists.

Once one Operation beats Standard Run in a paired playtest on repeatedness, clarity, memorable moments, and immediate replay intent, turn three Operations into a compact campaign season. Add async rivals next because most of that spine already exists. Only then build an invite-only two-player authoritative co-op slice. Competitive multiplayer and battle royale stay rejected until co-op netcode is stable and real concurrency evidence exists.
