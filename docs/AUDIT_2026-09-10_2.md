### 1 · `lint:strict` is red, and two sessions reported it green — HIGH

**Observed.** `npm run lint:strict` exits 1:

```
src/main.jsx
  20:7  warning  Fast refresh only works when a file has exports ...
                 react-refresh/only-export-components
✖ 1 problem (0 errors, 1 warning)
ESLint found too many warnings (maximum: 0).
```

**Root cause — the ruler moved, not the number.** `src/main.jsx` has not changed since
S163 (`94fd15d`). Dependabot PR #151 (`78efba4`, merged during S172) bumped
`eslint-plugin-react-refresh` 0.5.5 → 0.5.6, which extended
`only-export-components` to also flag a file with *no* exports. `src/main.jsx` is the
Vite entry: it is the HMR root, is never itself hot-refreshed as a component, and
correctly exports nothing. The warning is a false positive against an entry point.

**Reporting defect.** S172 and S173 both recorded "strict lint 0 errors". That is true
and misleading — the gate counts *warnings*, and exits 1. Both sessions read the error
count instead of the exit code, which is the exact failure the arc protocol warns about.

**Scope, stated honestly.** CI runs plain `npx eslint src` (blocks on errors only), not
`lint:strict` — `deploy.yml:34` even comments that "strict warning cleanup stays
local/optional for now". **Production deploys are not and were not blocked.** What is
broken is the local gate the session protocol and every SIL claim cite.

**Fix.** Scoped `eslint.config.js` override disabling the rule for the Vite entry, with
the reason written at the call site. Never raise `--max-warnings`. Add a regression
guard asserting every module entry in `index.html` is covered by that override, so the
exception cannot rot into a blanket waiver. Then promote CI to the strict gate so one
ruler governs both surfaces.

### 2 · Required closeout artifacts stale since S170, every gate green — HIGH

**Observed.** `docs/SESSION_PROTOCOL.md` §3.7 ("State vector + doctor + entropy +
genome") requires three renderers every closeout. Measured against git:

| Artifact | Renderer | Records | Behind |
|---|---|---|---|
| `context/STATE_VECTOR.json` | `render-state-vector.mjs` | S170 | 3 sessions |
| `context/GENOME_HISTORY.json` | `append-genome-snapshot.mjs` | S170 | 3 sessions |

**Scope checked, not assumed.** `context/STUDIO_MANIFEST.json` (last commit S170) and
`context/MEMORY_INDEX.md` (S169) look stale by git date and are **not**. The manifest is
regenerated from PROJECT_STATUS — `reconcile-studio-manifest.mjs` run this session
produced byte-identical output, so its git age only records when its inputs last
changed. MEMORY_INDEX has no writer script and no session marker at all; it is a static
navigation index, not a per-closeout artifact. Only session-keyed §3.7 artifacts can be
stale in this sense, and exactly two are.

Meanwhile all eight write-back surfaces are current at S173. STATE_VECTOR therefore
publishes `session: 170`, `silTotal: 997`, `silAvg3: 997.7`, `velocity: 6` and an S170
`currentFocus` — while PROJECT_STATUS says S173 / 995 / 995 / 2.

**Why nothing caught it.** Two probes exist and neither measures this:

- `protocol-drift-check.mjs:41` asserts `render-state-vector.mjs` **exists**
  (`- OK ... renders the canonical closeout state vector`). It never asserts the
  artifact that renderer produces is current. Presence is not currency.
- `check-writeback-currency.mjs` anchors on `SELF_IMPROVEMENT_LOOP.md` only. That file
  was written at S173, so F7 reports clean — correctly, for the question it asks.

Three consecutive closeouts skipped a mandatory protocol step and every gate stayed
green. This is the same defect class as F7 itself, one layer out.

**Fix.** A currency gate over closeout-owned artifacts that compares the session each
artifact records against the SIL ledger's newest closed-out session, wired into
`schema:lint` so a future skipped renderer fails loudly. Then bring the stale artifacts
current — or, where a renderer cannot honestly backfill three sessions it did not
observe, record that explicitly rather than fabricating the history.

### 3 · `silAvg3`/`silAvg5` are trusted, not derived — MED

**Observed.** `context/PROJECT_STATUS.json` carries `silAvg3: 995`; `STATE_VECTOR.json`
carries `silAvg3: 997.7`. From the append-only SIL ledger (S173=995, S172=991, S171=999)
the true 3-session average is 995.0 and the 5-session average (S170=997, S169=999) is
996.2. One surface is right by luck, the other is stale, and nothing compares either to
the ledger.

**Visible symptom.** A churn loop in git history: `5f7cb04` ("normalize SIL average
float formatting") rewrote `998.0` → `998`, S173's closeout hand-wrote `995.0`, and this
session opened with an uncommitted `995.0` → `995` reversal. `write-project-status.mjs`
serialises through `JSON.stringify`, which cannot preserve a trailing `.0`, so every
hand-authored float is reverted by the next script write, forever.

**Root cause.** `write-project-status.mjs` enforces `silScore := sum(silCategoriesV3)` —
"always recomputed, never trusted" — but leaves `silAvg3`/`silAvg5` as hand-entered
values with no authority behind them. The invariant discipline stops one field short.

**Fix.** Derive both averages from the SIL ledger inside the canonical writer, under the
same never-trusted rule. That removes the hand-entry, ends the float churn permanently,
and makes the two surfaces converge by construction.

### 4 · `coverage:check` reports FAIL for a missing prerequisite — LOW

**Observed.** `npm run coverage:check` on a clean tree prints
`Core gameplay logic coverage: FAIL` followed by
`ENOENT: no such file or directory, open '...coverage/coverage-summary.json'` and exits 1.
Coverage was never *measured*; the gate simply ran before `test:coverage` produced its
input. A gate that says FAIL when it means "not measured yet" trains readers to discount
it — the same honesty rule the rest of this repo enforces.

**Fix.** Distinguish "not measured" from "measured and failing", name the command that
produces the input, and keep a non-zero exit so it stays safe in a gate chain.
